# Learning Resources

## Official

- [MDN Web Docs: JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript) - the default reference.
- [MDN: Web APIs](https://developer.mozilla.org/en-US/docs/Web/API) - browser platform documentation.
- [Node.js documentation](https://nodejs.org/docs/latest/api/) - runtime and standard library.
- [Node.js learn](https://nodejs.org/en/learn) - official guides.
- [ECMAScript specification](https://tc39.es/ecma262/) - the language standard.
- [TC39 proposals](https://github.com/tc39/proposals) - what is coming next.
- [web.dev](https://web.dev/) - performance, accessibility, and modern web guidance.
- [npm docs](https://docs.npmjs.com/) - package and registry behavior.

## Books

| Book | Best for | Notes |
| --- | --- | --- |
| *Eloquent JavaScript* - Marijn Haverbeke | Beginner to intermediate | Free online; strong exercises |
| *You Don't Know JS Yet* - Kyle Simpson | Beginner to intermediate | Deep language semantics |
| *JavaScript: The Definitive Guide* - David Flanagan | Reference | Comprehensive |
| *JavaScript: The Good Parts* - Douglas Crockford | Historical | Dated but useful perspective |
| *Node.js Design Patterns* - Casciaro & Mammino | Intermediate to expert | Architecture and patterns |
| *Designing Data-Intensive Applications* - Martin Kleppmann | Expert | Not JS-specific; essential for distributed systems |
| *Site Reliability Engineering* - Google | Expert | Operations, SLOs, incident response |

## How to choose a resource

1. Start with MDN or Node.js docs for the API.
2. Use a book for structure and depth.
3. Use a talk or blog for production experience.
4. Use exercises and projects for skill.
5. Avoid collecting resources instead of finishing one.
